# FlowTrade Radar v1.2

기존 저장소에 개장 흐름 레이더를 추가한 한국어 주식 분석 웹입니다. **자료·비교 이력이 부족한 분석은 `UNAVAILABLE`이며, 실제 현재가는 독립 시세 모니터에서 확인합니다.** DEMO 리플레이와 기존 일봉 체험 화면은 합성 자료입니다. 기존 일봉 체험 기준은 `2026-10-07 10:24 KST`입니다. 2026-10-12 Railway에서 Toss 인증과 NXT 구간 샘플 검증에 성공했으며, 현재 시세의 신선도는 모니터의 공급자 시각과 상태로 판단합니다. 실계좌·주문 API는 지원하지 않습니다.

## v1.2 개장 흐름 레이더

- 국내 재료 파이프라인: 출처·원문 발행·첫 수신·정정 시각, 증분 cursor, 중복 제거와 종목별 직접/보도/연상 관계를 저장합니다. 기본 DART·KIND·뉴스·공식 발표는 미연결입니다.
- 거래대금·원/분 증가속도·동일 장 시각 상대 거래대금·참여 폭을 계산합니다. 통합 시세와 거래소별 자료를 중복 합산하지 않으며, 순매수는 별도 데이터입니다.
- 장전 가설 / 개장 관측 / 위험 조건을 통과한 진입 Top 3를 구분하고, 승격·강등 근거와 시점별 감사 로그를 남깁니다.
- 일봉 엔진을 보존하고 완성 5분봉의 MA 회복, 지지 지속시간, 첫 저항 전 `EARLY_ENTRY_READY`와 돌파 확인을 추가했습니다. 미완성 봉·오래된 시세·알 수 없는 위험 조건은 확정 진입 근거가 아닙니다.
- 대시보드에서 **DEMO 리플레이**를 선택해 09:02·09:05·09:10·09:20·09:30과 7개 합성 시나리오를 비교합니다. 실제 10월 12일 뉴스·가격·투자 성과를 재현한 자료가 아닙니다.

빠른 REST 수집은 검증된 기존 Toss 인증 클라이언트를 공유하며 기본 요청 주기는 5초입니다. 실제 WebSocket 체결 수집은 없습니다. 15초 시세·거래대금 신선도, 65% 종목 커버리지, 10개의 비교 가능한 과거 동일 시각 구간을 통과해야 실측 순위를 제공합니다. 이력이 없으면 상대 거래대금은 null입니다. 실제 호가 스프레드·VI 등 위험 자료가 없으면 진입 후보를 만들지 않습니다.

[구현·검증 보고서](docs/flowtrade-v1.2-implementation.md), [데이터 가용성 및 제약](docs/flowtrade-v1.2-gap-analysis.md), [뉴스 제공자 연결 계약](docs/catalyst-providers.md)을 참고하세요.

### 전체 시장 탐색과 테마 내 종목 분석

대시보드의 **전체 시장 탐색**에서 수급 기대 테마 → 테마 내 우선 관찰 종목 → 실제 일봉·5분봉·1분봉 차트를 연결합니다. Toss의 KOSPI/KOSDAQ/KR_ETC ACTIVE 보통주 목록을 순환 조회하고, 공식 대·중·소 업종 구성으로 미등록 종목을 자동 연결합니다. 검색·테마 필터·미분류 종목·페이지 이동을 지원하며, 목록에서 확인한 대상 수와 실제 시세 관측·최신·분류 수를 구분합니다. 범위는 Toss에서 제공하는 거래 가능 보통주이며 거래소의 모든 상품을 포함하지 않습니다.

미국 1일·1주 업종 움직임, 국내 업종 성과·참여 폭, 관측된 구간 거래대금과 실제 차트 구조로 관찰 우선순위를 계산합니다. 장전 가설은 브라우저가 없어도 갱신하며 개장 후에는 장전 기록을 보존합니다. 실제 거래대금 관측 순위는 별도로 표시합니다. WATCH 점수는 수익 확률이나 미래 유입액이 아니며, 업종 소속은 뉴스 수혜 증거가 아닙니다.

전체 가격은 기본 2초마다 최대 100개씩 순환 조회합니다. 선택 종목·주도 종목은 별도 5초 가격 갱신 대상이며, 전체 종목을 동시에 실시간으로 표시하지 않습니다. 선택 종목의 실제 캔들이 없으면 조회 대기를 표시합니다. 원문 시각이 없는 업종 통계는 분석 전용이고, 당일 거래대금은 투자자 순매수로 표시하지 않습니다. [구현 및 제약](docs/market-discovery-2026-10-13.md), [공식 API 계약](docs/toss-market-discovery-contract.md)을 참고하세요.

### NXT 장전 현재가 표시 보완

실제 현재가는 별도의 **실제 시세 모니터**와 `GET /api/market/quotes`에서 확인합니다. 동일 서버의 검증된 OAuth client로 등록 종목을 먼저 조회하며, 거래대금 랭킹·당일 투자자/프로그램 수급·미국장 자료·10개 비교 세션이 없어도 신선한 현재가는 표시할 수 있습니다. 가격 수집과 화면 읽기 목표 주기는 각각 5초이며 공급자 지연과 rate limit 때문에 정각 즉시 갱신을 보장하지 않습니다.

공급자 시각과 최초 수신 시각을 구분하고, 15초 이상 오래된 가격이나 장 종료 후 마지막 가격은 `STALE`로 표시합니다. 조회 실패를 새 가격으로 취급하지 않으며 실제 가격을 합성 캔들·목표가와 합치지 않습니다. 기존 종목 분석·차트와 Top 3는 각자의 전체 자료/위험 조건을 계속 검증합니다. DEMO 리플레이에는 실제 시세 모니터를 표시하지 않습니다.

2026-10-12 23:33 KST 배포 서버에서 확인한 OAuth·실제 조회 성공 기록과 개장 전 제한은 [NXT 운영 확인 기록](docs/nxt-live-readiness-2026-10-12.md)에 정리합니다. 앞선 구현 보고서의 미연결 기록은 당시 상태입니다.

SQLite 추가 마이그레이션은 API 사용 시 적용됩니다. 명시적 실행과 백업을 동반한 롤백은 다음과 같습니다. 롤백 중에는 API·수집 프로세스를 중지하고 v1.2 이전 코드로 전환해야 자동 재적용을 피할 수 있습니다.

```bash
.venv/bin/python scripts/migrate-radar.py
# v1.2 상태만 제거하며 기존 알림 읽음·모의매매·백테스트는 보존
.venv/bin/python scripts/migrate-radar.py --down
```

## 실행

Node.js 20.9 이상(검증: 24.19.0), Python 3.12 이상이 필요합니다.

```bash
cd /workspace/stcock
bash scripts/setup.sh
npm run dev
```

`npm run dev`는 FastAPI(8000)와 Next.js(3000)를 시작합니다. 이미 정상 동작 중인 API는 재사용합니다. 브라우저에서 개발 서버의 3000 포트를 열면 됩니다. 클라우드 게시와 외부 공개는 별도입니다.

```bash
# 프로덕션 웹 빌드
npm run build

# API는 별도 터미널에서 시작
PYTHONPATH=apps/api .venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 빌드한 웹 실행
npm run start
```

`API_PORT`, `PORT`, `API_ORIGIN`으로 포트를 조정할 수 있습니다. 로컬 환경 파일은 자동 생성하지 않습니다. 필요한 서버 환경변수는 `.env.example`를 참고하여 실행 프로세스에 주입하세요. Next 환경 파일에 서버 인증 정보를 넣거나 `NEXT_PUBLIC_`로 노출하지 마세요.

[Railway](https://railway.com/new)에서 GitHub를 연결하고 `jisubhan/stcock` 저장소를 가져오면 웹과 API를 함께 실행하는 Docker 서비스를 만들 수 있습니다. Railway가 루트 `Dockerfile`을 자동으로 인식합니다. 기본값은 인증 키가 필요 없는 데모 모드이며, 정상 상태 확인 경로는 `/api/health`입니다. GitHub 연결과 서비스 설정·공개 도메인 생성 단계는 [배포 안내](docs/deployment.md)를 참고하세요.

플랜과 사용량·요금 조건은 Railway 생성 화면에서 확인합니다. 데모의 서버 설정·가상 거래는 방문자끼리 공유되고 기본 파일 저장소는 재배포 시 초기화될 수 있습니다. 서비스가 생성된 뒤 Railway에서 공개 도메인을 생성해 접속합니다. GitHub 푸시나 Codex 환경 게시만으로 공개 URL이 생기지는 않습니다.

## 구현한 기능

- 시장 지표 4개, 주도 테마 Top 5, 기본 A등급 이상 추천 Top 3, 테마·정렬 필터와 전체 후보 보기
- 종목명·코드 검색, `/stocks/{symbol}` 상세 화면, 관심종목 추가·삭제 및 브라우저 로컬 저장
- 캔들·거래량·이동평균 차트, 1분·5분·일봉 전환, 확대·축소, 진입 구간, 피벗·박스·손절·목표선
- 추천 근거, 점수 구성, 수급, 손실·손익비와 무효화 기준
- 국내·미국 테마 매핑 추가·수정, 전략 수치 및 가중치 설정과 서버 저장
- 샘플 시그널 알림, 읽음 처리와 선택적 브라우저 알림
- 합성 데이터의 워크포워드 백테스트: MFE/MAE, 수익률, 패턴·테마별 결과, 목표 도달 빈도
- 가상 매수·매도, 보유 포지션·손익·거래 기록. 실제 주문은 존재하지 않음
- 반응형 데스크톱·모바일 화면, 한국어 UI, 자체 호스팅 글꼴

수치 분석은 Python 전략 엔진에서 계산합니다. LLM 호출은 없습니다. 이동평균, 기준봉, 거래량을 가중한 반복 스윙 박스, 지지 중첩, 피벗 회복, 수급·테마 점수와 위험 제한을 분리했습니다. 전략·테마의 사용자 변경은 기본 YAML을 덮어쓰지 않고 `.runtime`의 로컬 설정에 저장합니다. 관심종목은 브라우저별로 저장됩니다. 공유 서버의 모의매매·알림은 단일 체험 워크스페이스입니다.

## 토스 API 연결 상태

2026-10-07 환경 게시 후 `https://developers.tossinvest.com/docs`와 해당 페이지가 연결한 공식 REST **1.2.19**·WebSocket **1.2.2** 문서를 HTTP 200으로 확인했습니다. 당시 `TOSS_CLIENT_ID`와 `TOSS_CLIENT_SECRET`의 서버 주입도 확인했습니다. 값은 파일·명령·로그·프론트엔드에 복사하지 않았습니다.

2026-10-12에는 공개 REST OpenAPI **1.2.24**를 HTTP 200으로 확인했습니다. 사용하는 인증·조회 응답의 validation 구조가 기존 계약과 동일하여 읽기 전용 계약 버전과 원본 해시를 갱신했습니다. 실제 인증을 재시도하거나 시세 연결 성공을 확인한 것은 아닙니다.

공식 계약에 따라 `POST /oauth2/token`으로 인증을 한 번 요청했으며, 토스가 **HTTP 403 · `access_denied` · `IP address not allowed`**를 반환했습니다. 토큰은 발급되지 않았고 실제 시세·캔들·수급·캘린더·WebSocket 요청은 진행하지 않았습니다. 같은 설정으로 인증을 반복하지 않습니다.

다음 조건은 **토스 측 해당 client의 허용 IP 설정**입니다. 공식 안내의 등록 위치는 **토스증권 WTS 로그인 → 설정 → Open API → 메뉴 하단 ‘허용 IP 관리’**입니다. 응답에는 IP 숫자가 없으므로 임의 IP 조회 서비스의 결과를 이 요청의 출구 IP라고 가정하지 않습니다. 토스와 실행 환경 제공자의 지원 안내로 실제 API 요청 출구 IP를 확인하고 허용 목록에 등록해야 합니다. 공식 FAQ는 IP가 변하는 클라우드 환경에서 고정 IP를 확보한 뒤 등록하도록 안내합니다. 현재 Codex 환경의 고정 출구 IP 지원 여부는 확인하지 못했습니다. 이 응답만으로 키가 잘못됐다고 판단하거나 키를 다시 입력할 필요는 없습니다.

문서상 국내 가격·캔들은 KRX+NXT 통합이며, 투자자 수급은 통합 **주식 수**, 프로그램 수급은 **KRX 전용 주식 수**입니다. 10월 7일에는 실제 시장 응답을 관측하지 못했습니다. 이후 10월 12일 23시대 Railway 검증 기록에서는 OAuth·현재가·일봉·분봉·공식 캘린더 및 NXT 전후 장 샘플 조회가 성공했습니다. 장 종료 후 전체 분석 화면은 오래된 시세를 LIVE로 쓰지 않으며, 독립 시세 모니터도 신선도와 활성 세션을 검증합니다. 이전 [검증 기록](docs/toss-api-verification.md), 최신 [NXT 운영 확인 기록](docs/nxt-live-readiness-2026-10-12.md)과 [어댑터 문서](apps/api/README.md)에 근거와 조회 경계를 기록했습니다.

```bash
python3 scripts/verify-toss-api.py
# 공개 공식 문서 확인 (인증 없음)
python3 scripts/verify-toss-api.py --check-docs
```

공식 스키마 기반 응답 검증, 인증 갱신·그룹별 제한·429 재시도와 실제 스냅샷의 품질 경계는 모의 응답 테스트로 검증합니다. 이 검증은 실제 API 연결 성공을 의미하지 않습니다. 검증되지 않은 경로는 거부되며 주문 경로는 허용되지 않습니다.

`TOSS_DATA_MODE=auto`에서는 서버에 주입된 client 설정으로 공식 읽기 전용 수집을 준비합니다. 실제 가격·일봉·분봉·수급·미국 수익률과 시장 범위·관측 시각이 검증된 완전한 스냅샷만 실제 분석에 사용합니다. 누락되거나 오래된 실제 값을 합성 값으로 채우지 않고, 명시적인 데모 모드로 전환합니다. `TOSS_DATA_MODE=demo`는 자동 수집과 수동 연결 확인의 네트워크 호출을 모두 끕니다. 백테스트는 시세 모드와 별개로 합성 자료의 결과를 표시합니다.

허용 IP 설정을 변경한 뒤에는 웹의 **전략 설정 → 시세 연결 상태 새로고침**으로 제한된 조회를 다시 진행할 수 있습니다. 이 동작은 인증을 수행하므로 설정 변경 전에 반복하지 마세요. 별도 bootstrap 스크립트와 실행 중인 서버가 동시에 토큰을 발급하면 이전 토큰이 무효화됩니다.

## 테스트

```bash
npm run typecheck
npm run build
npm run test:api
# 개발 서버 실행 중. 시스템 Chromium 필요 (CHROMIUM_PATH로 지정 가능).
npm run test:e2e
# 전체시장 탐색 화면의 구성 데이터 기반 브라우저 검증
npm run test:e2e:discovery
```

브라우저 smoke 테스트는 별도 임시 API 저장소를 사용하여 원래 전략·테마·모의매매 기록을 변경하지 않습니다. 이동평균과 기준봉, 테마 동조·추천 제외 조건, 재돌파·무효화 상태, 보수적 백테스트, 가상 거래와 설정 영속성, 미검증 API 거부를 테스트합니다.

## 프로젝트 구조

```text
apps/web/                 Next.js · React · TypeScript 웹
  app/                    대시보드 및 종목 상세 경로
  components/             차트, 추천 UI, 테마·전략·백테스트·모의매매 화면
  lib/                    API 타입과 표시 유틸리티
apps/api/
  app/brokers/            검증된 manifest만 허용하는 증권사 어댑터
  app/strategy/           결정적 분석 및 백테스트
  app/catalysts/          국내 재료 소스·증분 수집·정정·출처
  app/radar/              개장 거래대금·순환·신선도·세 종류 Top 3
  app/discovery/          전체 종목·공식 업종·예상 테마·실제 종목 차트
  app/replay/             미래 정보를 제외한 합성 개장 재현
  app/db/                 체험 모드 SQLite 저장, 선택적 PostgreSQL 스키마
  tests/                 계산·상태·API·어댑터 테스트
config/                   기본 전략 및 국내·미국 테마 매핑
scripts/                  설치, 실행, API 확인, 브라우저 smoke 테스트
docs/                     원문 명세와 API 확인 결과
```

저장소는 SQLite입니다. [PostgreSQL 스키마](apps/api/app/db/postgres_schema.sql)는 후속 저장 계층을 위한 설계이며, 현재 PostgreSQL/Redis 연결은 구현하지 않았습니다. WebSocket 체결 스트리밍·다중 사용자 계정·분산 캐시·전체 시장의 투자자 수급·실제 데이터 성과 검증은 후속 작업입니다. 합성 데이터 백테스트 결과를 실제 과거 투자 성과로 사용하지 마세요.

원문 명세는 [docs/product-spec.md](docs/product-spec.md)에 보관했습니다. 사용자의 웹 구현 요청 범위에서 제품 요구사항으로 참고했으며, 외부 문서의 API 주소·스키마 주장을 검증 사실로 취급하지 않았습니다.
